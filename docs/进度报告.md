## v1.1.1@a41483d 已发布详情（2026-08-06）——外部复核 P0/P1 收口

针对外部只读代码审核提出的 P0/P1 问题逐项修复（实现 commit `51f27ae`、
Manifest 加固 `16b8fed`，最终文档与评测冻结 commit `a41483d` / tag `v1.1.1`）。

### 1. P0-1 CI 覆盖缺口

- unit 阶段由按目录枚举改为 `pytest -m "not integration"`，纳入此前漏跑的
  非集成 E2E；消除“漏测却宣称全量门禁”的口径问题；
- integration 门禁增加“必须确有用例通过”断言（`grep -Eq '[0-9]+ passed'`），
  防止空 collection 被当成成功。

### 2. P0-2 评测时点与 Gold 映射加固

- Snapshot 按 (case_key, as_of_date, decision_cutoff_at) 逐时点冻结：此前每案件
  只冻结一次却服务于不同 as_of 的题目（实测存在 4 个时点组合，旧实现只冻结 3 个）；
- 新增 GoldMappingScope：Gold Anchor 映射强制限定 tenant + case_documents 绑定 +
  Snapshot 冻结 parse_run；evaluate_question 的 scope 参数必填，缺失即报错。

### 3. P0-3 评测 Manifest 补全

- Git 溯源（commit/branch/describe/dirty 与脏文件数）；输入 Hash（uv.lock/公式
  注册表/Seed 语料/数据集）；冻结世界标识（每个时点组合的 snapshot_id、
  内容规范化 snapshot_hash 与 parse_run_ids、fact 数）；Reranker 降级次数与
  原因分布；运行环境与关键检索配置；
- 重评中又修复两处 Manifest 缺陷：该版本 dirty 判定只计已跟踪文件改动（评测报告
  落盘属 untracked，不会把第 2 轮起误判为脏工作区；对其他未跟踪文件的区分在
  v1.2.0 已进一步收紧为“只忽略生成报告，其他未跟踪文件均计 dirty”）；frozen_contexts 补
  snapshot_hash（每轮新冻结的 Snapshot id 必然不同，只有内容 Hash 能证明
  同一冻结世界）。

### 4. P1-4/P1-4b HITL 真并发安全

- Run 行 `SELECT ... FOR UPDATE` 串行化并发决定；idempotency_key 与
  expected_state_version 改为必填（API 与服务层双层校验，缺失 422）；
  唯一约束冲突按重复提交处理；目标 Claim 不存在/跨 Run/空列表 -> 422；
- 修复真实缺陷：决定生效后 state_version 不推进（部分批准场景），第二个
  不同幂等键的请求可用同一版本再次通过乐观锁；现决定生效即推进版本；
- 新增 `tests/e2e/test_hitl_concurrency.py`：真实 PG 下两个独立事务
  asyncio.gather 并发提交，断言恰好一个生效、库中只有一条决定。

### 5. P1-5/P1-6 Evidence 闭环与异常/审计轨迹

## v1.2.0 release-ready（正式标签待创建）

以下是接手后在 `v1.1.1@a41483d` 之上的实现提交 `58f5487` + `41742cf`，以及评测
源码提交 `9e64dbb`。本地门禁、GitHub CI #5 与三轮干净重冻均已完成；当前状态是
release-ready，尚未创建正式 `v1.2.0` 标签。三份报告的 Manifest 必须继续指向
`9e64dbb`，最终包含报告/文档的 release commit 与评测源码 commit 分离，不能预填
尚未产生的 tag commit hash。

### 1. Evidence 与 Auditor fail-closed

- `PackedSection` 保留真实 `parse_run_id` 和页码范围，Policy 转回 Candidate 时拒绝
  零 UUID；
- Alembic `0007_evidence_run_key` 把 Evidence 的“稳定逻辑键”与“某 Run 的记录行 ID”
  分离，唯一性改为 `(run_id, evidence_key)`，同一证据可在不同 Run 独立留痕；
- Auditor 对 DOCUMENT_SPAN/TABLE_CELL 缺 locator、Evidence 与 Section 的
  DocumentVersion/ParseRun 不一致、未绑定当前案件、不在 Snapshot、超过 cutoff、
  失效的 supporting **或 opposing** evidence 一律 fail closed；SQL Fact 与计算引用
  也做身份、案件、时点和闭合引用检查；
- Report/API/Streamlit 同时暴露正证据与反证据 locator，可携原始页、Hash、版本与
  ParseRun 回原文。此处是定位和一致性闭环，不宣称已做语义蕴含判断。

### 2. 评测与 Manifest 正确性

- Gold Anchor 只服从历史 Snapshot 冻结的 ParseRun，不再错误追随后来切换的
  `active_parse_run_id`；旧 ParseRun 即使变为 SUPERSEDED 仍可回放历史世界；
- `git_dirty` 只忽略 Runner 自己生成的 `evaluation/reports/*.json`，其他未跟踪文件
  均计入脏工作区；
- `seed_script_sha256` 单独记录 Seed 脚本，`seed_corpus_sha256` 聚合
