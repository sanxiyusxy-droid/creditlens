# CreditLens v1.6 演示闭环与评测实证

> 状态：开发候选，尚未发布。
> 更新日期：2026-08-30。
> 适用范围：深 RAG/Trace 展示、一键本地演示、HTTP 黑盒验收、答案重评、
> Multi-Agent 消融与 fail-closed 案例。
> 证据规则：只有真实运行产物可以写成结果；Schema、Runner、模板或 Mock 测试就绪，
> 只能写成“能力已实现/待实跑”，不能替代效果指标或真实栈验收。

## 1. 版本目标与非目标

v1.6 不改变 CreditLens “授信审查辅助而非自动授信”的产品边界。它解决的是上一版本
“能力已经存在，但面试演示不够直观、启动依赖人工准备、验收与效果证据没有统一入口”
的问题：

1. 把 Query Rewrite、多路召回、RRF、精排、Context Packing 和调用账本直接展示出来；
2. 把迁移、RLS、合成数据、索引、财务事实、前置检查、API、HTTP 验收和 UI 串成一个入口；
3. 用 HTTP 合约而不是内部函数拼接验证“问答 → 完整预审 → 可选 HITL → 报告 → Trace”；
4. 为 3 题 smoke 与 41 题完整答案重评建立 gold 隔离、断点产物和评分规约；
5. 为 FULL、去 Challenger、去 Auditor、单 Agent 基线建立可审计消融规约；
6. 用可复现的真实执行失败案例证明系统会阻断、转人工且不生成报告。

本版不宣称已经完成真实银行数据验证、生产认证、持久业务任务队列、Run lease、
Exactly-once、完整 OTel 或自动授信。Multi-Agent 消融是离线 deterministic component
harness，不是 Supervisor/LLM/HTTP/DB/RAG 端到端运行，也不是可部署模式。

## 3. 总体架构

```text
start_demo.ps1
  ├─ 固定本地 Compose 基础设施与 demo identity
  ├─ Alembic upgrade → RLS/最小权限
  ├─ 幂等 Seed → Qdrant Alias/Point → FinancialFact
  ├─ fail-closed Preflight
  ├─ FastAPI
  ├─ HTTP Acceptance
  │    Question → QA Trace → FULL_REVIEW → [HITL] → Report → Run Trace
  └─ Streamlit
       ├─ Deep RAG：QuerySpec → Routes → RRF → Rerank → Packing
       └─ Audit：Invocation Ledger → Telemetry Outbox → RunEvent

Evaluation
  ├─ Answer re-evaluation：query-only online → raw checkpoint → gold mapping → score
  ├─ Agent ablation：frozen scenarios × 4 variants → complete observations → score
  └─ Fail-closed：真实执行注入 → terminal state/artifact/report/trace assertions
```

关键边界是：启动器负责准备和证明环境，HTTP Runner 负责证明公开 API 闭环，评测 Runner
负责证明效果；三者不能互相代替。页面能显示一条 Trace，不等于真实栈完整验收已通过；
Schema 能计算指标，也不等于已经存在可引用的观测结果。

## 4. 六项功能技术设计

### 4.1 深 RAG 与 Trace 可视化

实现入口：

- `apps/demo/streamlit_app.py`
- `apps/demo/presenter.py`
- `apps/demo/http_client.py`
- `tests/unit/test_demo_presenter.py`

Grounded QA 返回后，页面以独立展开区展示服务端已经返回的事实，不在前端推测：

1. **QuerySpec**：原问题、standalone query、意图、产品、`as_of_date`、
   `decision_cutoff_at`、术语归一、精确词与 `must_not_assume`；
2. **Query Variants**：variant/subquery、来源、目标 route 和实际文本；
3. **Dense/Sparse/Summary/Exact**：是否执行、变体数、候选数、拒绝数；明确区分
   “路由未执行”和“执行后 0 命中”；
4. **候选拒绝**：按 route/variant 汇总服务端 rejection reason，不回显被拒正文；
5. **RRF 与精排**：`rrf_k`、输入列表、融合/最终候选数，及 rerank 的
   applied/degraded/reason/version；精排降级时明确说明继续使用 RRF 顺序；
6. **Context Packing**：预算、估算 Token、入选/展开/丢弃数量以及页码和 heading。

Run Trace 页面同时展示：

- `invocation_v2` MODEL/TOOL 的名称、四类终态、延迟、安全错误码和 Invocation ID；
- 每条调用的账本完整性、Outbox delivery 状态与投递次数；
- Delivery 汇总计数和原有 `run_events`。

六态必须这样解释：

- `EMPTY`：v2 Run 当前没有已提交调用记录；不证明从未发生调用；
- `MISSING`：合法 InvocationRecord 缺少同事务 Outbox；
- `INVALID`：payload、Hash、投影或业务绑定校验失败；
- `PENDING`：仍有待投递或租约处理中的 Outbox；
- `COMPLETE`：当前持久集合有效且已投递，不证明 expected invocation 全覆盖；
- `DEGRADED`：存在 dead-letter 或其他不可完整投递状态。

历史 Run 没有 `invocation_v2` 时显示 `LEGACY_UNAVAILABLE`，而不是伪装成零调用。缺少
可选新字段时 presenter fail-soft，仍允许查看旧响应的答案和事件。

面试讲法：页面的价值不是“多了一张表”，而是把检索链每个损失点可观测化。面试官可以
从 Query Rewrite 是否改坏关键数字、某路为何无候选、候选为何被权限/时点门禁拒绝、
精排是否降级、Packing 是否因预算丢证据一路定位问题。

### 4.2 一键 bootstrap

主入口：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\start_demo.ps1
```

默认路径是确定性、无外部模型网络调用的合成演示配置：

- LLM disabled，允许抽取式 QA fallback；
- hash embedding；
- lexical rerank fallback；
- PostgreSQL/Qdrant/MinIO 地址强制固定在本机；
- demo identity 必须显式启用，不能把该配置带入 production。

脚本依次执行：`uv sync --frozen`、启动本地 Compose、等待 PostgreSQL/Qdrant/MinIO、
Alembic 到 head、应用 RLS/最小权限、幂等 Seed、补齐三案件共 12 条合成
`FinancialFact`、运行 preflight、启动 API、执行 HTTP 验收、启动 Streamlit。它不执行
`compose down`、drop、reset 或删除 volume，已有数据与卷被保留。

HTTP 验收要求 FULL_REVIEW Trace 达到 `COMPLETE` 且每条 Invocation 为 `DELIVERED`，因此
启动器会在 `local` 环境显式开启 `local_directory` 演示 Exporter。它为每个 Invocation 生成
一份以 UUID 命名的 canonical JSON，写临时文件、`fsync` 后原子替换到
`evaluation/reports/local/telemetry_delivery/`；相同 UUID/相同字节重试是幂等成功，不同
内容则 fail closed。API 只允许 local/development/dev/test 配置该后端，并要求目标位于 Git
忽略的 `evaluation/reports/local/` 下。内置 Noop 不会丢弃后假装成功，仍然 fail closed；
默认产品配置仍关闭 Worker。这个目录 Exporter 只解决本机演示验收，不是生产遥测系统，生产
仍需独立 Worker 身份、专用幂等 Exporter、外部指标平台和告警。

常用参数：

| 参数 | 用途 | 风险边界 |
|---|---|---|
| `-BootstrapOnly` | 只准备和前检，不启动 API/UI | 适合演示前预热 |
| `-SkipCompose` | 复用已经由操作者启动的本地 Compose | 仍会执行 readiness/preflight |
| `-SkipSync` | 跳过依赖同步 | 只在依赖已经严格同步时使用 |
| `-SkipHttpAcceptance` | 显式跳过 HTTP 验收 | 不能再声称本次启动完成全链验收 |
| `-UseConfiguredModels` | 允许使用 `.env.local` 中的模型配置 | 会让合成材料离开本机，必须显式授权 |
| `-AcceptanceTimeoutSeconds N` | 调整完整预审轮询超时 | 不是生产 SLA |

推荐的独立前检命令仍由 PowerShell 入口负责固定安全环境：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\start_demo.ps1 -BootstrapOnly
```

底层 Python 入口如下，但它不会替调用方改写数据库、Qdrant、MinIO、身份或模型环境；只有在
操作者已经显式准备了与启动器相同的 local demo 配置时才直接使用：

```powershell
uv run python scripts/bootstrap_demo.py
uv run python scripts/bootstrap_demo.py --check-only
```

使用已配置模型时必须双重显式：PowerShell 的 `-UseConfiguredModels` 会把
`--allow-configured-models` 传给 Python 配置门禁。未授权却发现外部 LLM/Embedding/Rerank
配置，preflight 以稳定错误码失败，不会静默出网。

Preflight 检查四组事实：

- configuration：local/demo identity、本机 PG/Qdrant/MinIO、模型授权；
- postgres：运行角色不是 superuser/bypass RLS、Alembic head、8 张关键表强制 RLS、
  禁止过宽授权、三案件和财务事实完整；
- qdrant：chunk/summary 两个 Alias 指向预期物理 Collection、状态健康、Point 非空；
- minio：raw/parsed/rendered 三个 Bucket 均存在。

输出是单一安全 JSON 文档，只返回稳定 code 和异常类型，不回显 DSN、密钥、服务 URL、
SQL 或底层异常正文；任何组件失败都会令 `ready=false`。

### 4.3 完整 HTTP 演示验收

入口：

```powershell
uv run python scripts/http_demo_acceptance.py
uv run python scripts/http_demo_acceptance.py --base-url http://127.0.0.1:8000 `
  --timeout-seconds 120 --poll-seconds 0.5
```

CLI 默认只允许 `localhost/127.0.0.1/::1`；非 loopback 必须显式
`--allow-non-loopback`，避免验收脚本意外向远端案件服务写入 Question/Run/HITL 决定。

Runner 只通过公开 HTTP 合约操作：

1. `GET /health/ready`；
2. `GET /api/v1/cases/{case_id}`；
3. `POST /api/v1/cases/{case_id}/questions`；
4. 校验候选非空、SUPPORTED Claim 有 citation、QuerySpec、四路 Trace、RRF、rerank 状态和
   Packing 预算；
5. 读取 QA Run 和 QA Trace；
6. `POST /api/v1/cases/{case_id}/runs` 启动 `FULL_REVIEW`，轮询到终态；
7. 若为 `HUMAN_REVIEW`，不会“批准所有 blocking Claim”；只有完整 blocking 集合与冻结的
   allowlist **精确相等**才继续。可批准 Claim 必须是 `DATA_CONFLICT + PARTIALLY_SUPPORTED +
   PENDING`，且必须唯一关联一条 source Claim、同时具备正反两侧 Evidence。指纹覆盖冲突与
   source 的 statement/category/verdict，以及 Evidence 的正反绑定、类型、content hash 和
   locator 身份；随机 run/claim UUID 不进入 Hash，以便重复 Seed 后仍可复核，但 UUID 格式、
   source 唯一性与非自引用会在计算前校验。任一新增、缺失、变更或不可规范化 Claim 都
   fail closed；
8. 对 allowlist 命中的 Claim 提交带幂等键和 `expected_state_version` 的人工决定，要求最终
   `COMPLETED`；
9. 读取报告，要求 `APPROVED_DRAFT`、run_id/version/content 结构正确，并按生产 JSON canonical
   方式重算 `content_hash`；
10. 轮询 Run Trace 到 aggregate `COMPLETE`；QA 的确定性零调用可以是 `EMPTY`，FULL_REVIEW
    必须有 Invocation，且每条完整性有效、Delivery 恰为 `DELIVERED`。

HITL allowlist 默认读取 `evaluation/datasets/http_acceptance_hitl_v1.json`。本轮已在真实
栈核对冲突 Statement 与证据并冻结两条指纹；如果文件不存在而 Run 进入 HUMAN_REVIEW，
Runner 会报 `HITL_EXPECTATION_REQUIRED`，不会为了让 Demo 通过而自动批准。

验收失败只输出稳定错误码，不输出响应正文或 Provider 细节。注意测试层级：MockTransport
证明 Runner 会真正按 HTTP 方法、路径和合约判断；ASGITransport 证明 FastAPI 应用合约；
只有对已启动 `127.0.0.1:8000` 执行上述 CLI，才能称为本机完整 HTTP 黑盒演示验收。

`427b8e45baebbd97a3bbab7c6d3b2395c88c38f7de94bd2bfc2b40d88c191984`。结果为

### 4.4 v1.5 答案重评：3 题 smoke + 41 题 full

入口：`scripts/run_v16_answer_reevaluation.py`。冻结 Manifest 固定：

- query-only 数据：`evaluation/datasets/answer_eval_queries_v1.json`；
- 答案标签：`evaluation/datasets/answer_eval_v1.json`；
- source gold：`evaluation/datasets/frozen_v2.json`；
- `top_k=8`；
- 阶段为 3 题 smoke 与 41 题 full；
- gold 边界为 `ONLINE_QUERY_ONLY_THEN_OFFLINE_GOLD_MAPPING`。

默认命令只生成计划，不调用模型，也不产生指标：

```powershell
uv run python scripts/run_v16_answer_reevaluation.py
```

经授权后才实际执行。正式完整运行使用 `all`，Runner 会在同一个 run root 内先执行并验证
smoke，只有通过后才继续 full；`full` 不能脱离本轮 smoke 单独启动：

```powershell
uv run python scripts/run_v16_answer_reevaluation.py --stage all --execute
```

在线阶段由既有 prediction runner 只读取 query projection；全部原始 QA checkpoint 完成后，
suite 才第一次读取答案标签/source gold，核对 query/answer/gold/prediction Hash，生成该阶段
严格计数的 scoring dataset，再在独立进程评分。任一阶段生成、验证或评分失败，
`run_manifest.json` 会记录 `FAILED` 和 failure phase，不会把部分结果当完整报告。

本轮还增加了 **freshness gate**：smoke/full 每个阶段生成独立 `execution_nonce`，将它纳入
experiment hash、QA 幂等键、raw checkpoint、prediction metadata 和 suite manifest。后置验证
要求业务预测的 `idempotent_replay_count=0`；只要命中旧请求重放就以 `VALIDATION` 失败，
避免“脚本重新执行了，但答案其实来自 v1.5 旧缓存”被误报成新重评。该机制已通过答案/HTTP
定向测试，并已由本轮 3+41 实跑证明每阶段 `idempotent_replay_count=0`。

### 4.5 Multi-Agent 消融

冻结数据集：`evaluation/datasets/agent_ablation_v1.json`。当前矩阵为 6 个场景 × 4 个变体：

| 变体 | 执行语义 | 说明 |
|---|---|---|
| `FULL` | `DETERMINISTIC_COMPONENT_HARNESS` | 启用 Contract Validator、Challenger conflict assessment 与确定性 HITL policy |
| `NO_CHALLENGER` | `DETERMINISTIC_COMPONENT_HARNESS` | 关闭 conflict assessment，保留 Contract/Auditor 门禁 |
| `NO_AUDITOR` | `DETERMINISTIC_COMPONENT_HARNESS` | 关闭 Contract/Auditor 与其 HITL，保留 Challenger；仅评测 |
| `SINGLE_AGENT_BASELINE` | `DETERMINISTIC_COMPONENT_HARNESS` | 同时关闭 Challenger/Auditor 决策；不是 live single-Agent |

六个场景覆盖无事实绑定的数字 Claim、越权审批语句、未知 Evidence ID、同期间数字冲突、
期间错配补充材料与完整支持的政策 Claim。Collector 复用生产
`validate_artifact_contract()` 与 Challenger `assess_conflict()`，但不启动 Supervisor、LLM、
HTTP、数据库、向量库、检索、持久化或外部服务。反证文本由冻结 fixture 注入，故
counter-evidence recall 只衡量组件是否处理目标，不是检索召回率。

执行 24 个 cell，并为每个 cell 生成可校验 JSON sidecar：

```powershell
uv run python scripts/run_agent_ablation.py `
  --collect evaluation/reports/local/<new-empty-output-dir>
```

每条 Observation 绑定 sidecar 相对路径与 SHA-256；评分前会重读 sidecar，校验 Schema、Hash、
scenario/variant/run/time/输出/延迟相关性，并基于 frozen dataset 重建输入、重跑
`validate_artifact_contract()` / `assess_conflict()`。因此即使同时篡改 sidecar、Observation
并重算 SHA，也会因原语重算不一致 fail closed；缺任一 6×4 cell 同样拒绝评分。已有
Observation 也可再次独立评分：

```powershell
uv run python scripts/run_agent_ablation.py `
  --observations <output-dir>/observations.json `
  --artifact-root <output-dir> `
  --output <output-dir>/rescored_report.json
```

## 7. 禁止表述

- 不得只报拒答率而隐去本轮可回答题质量偏低和 4 次技术失败；
- 组件消融不得写成 Supervisor/LLM/HTTP/DB/RAG 端到端或线上 Agent 增益；counter evidence
  是冻结注入，P95 是本地组件耗时，Token/成本 coverage=0；
- contract-only 预检不得写成系统门禁实证；最终两例也不得写成外部模型或 HTTP 安全率；
- MockTransport/ASGITransport 与本轮 TCP HTTP 证据必须分层披露；
- UI 展示候选拒绝不得说成前端重新执行了安全过滤；前端只展示服务端事实；
- `COMPLETE` 不等于所有现实调用都已入账，`EMPTY` 不等于一定没有调用；
- `DETERMINISTIC_COMPONENT_HARNESS` 不得写成可部署的 no-auditor/no-challenger 模式；
- Citation-set F1 不得称为 Faithfulness，词面分数不得称为语义准确率；
- 本版仍是合成数据原型，不得写成生产银行系统或自动授信系统。
